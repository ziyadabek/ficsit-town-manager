В рамках Этапа 2 были последовательно устранены все подтверждённые проблемы и дефекты, выявленные на этапе технического аудита (`AUDIT_REPORT.md`), с соблюдением строгой обратной совместимости и сохранением функциональности:

## 4. Архитектурные решения и обоснование правок

### 4.1. Двухуровневое хранилище (IndexedDB + localStorage)
*Проблема*: Браузерный `localStorage` ограничен 5 МБ. При сохранении крупных графов (100+ узлов и 150+ рёбер) квота быстро исчерпывается. Проект использует подход «метаданные в localStorage, тяжёлые снимки в IndexedDB». Однако при загрузке `initStorage()` легковесный объект без полей `nodes`/`edges` затирал полный снимок из IndexedDB.  
*Решение*: Разработан алгоритм консервативного слияния:
```javascript
export function mergeFrozenStagesWithIdb(idbStages = {}, memStages = {}) {
  // Если в оперативной памяти/localStorage снимок пуст, а в IDB он полный — 
  // сохраняем полный снимок из IDB.
}
```
Это позволило сохранить мгновенную синхронную инициализацию интерфейса без риска потери сохранённых топологий фабрик.

### 4.2. Селективная реактивность Zustand
*Проблема*: Использование деструктуризации из полного стора (`const { nodes, edges } = useFactoryStore()`) подписывает компонент на абсолютно любое изменение в сторе (например, на клик чекбокса станка, изменение режима сортировки или ввод в поле фильтра).  
*Решение*: Перевод всех компонентов верхнего и среднего уровней на явные стрелочные функции-селекторы:
```javascript
const storeNodes = useFactoryStore(s => s.nodes);
```
Zustand выполняет строгое сравнение по ссылке (`===`), что предотвратило ненужные ререндеры тяжелых деревьев React Flow и таблиц.

### 4.3. Рециркуляция жидкостей (VIP Junction)
*Проблема*: В Satisfactory побочная вода из процессов глинозёма должна иметь наивысший приоритет потребления, иначе производство блокируется. В реалистичном графе узел `vip_water` не обрабатывался стандартным циклом групп рецептов.  
*Решение*: В секции 5.1 движка графов выделена отдельная фаза связывания входящих потоков для узлов со специальным флагом `data.isVIP`, собирающая как входящую вторичную воду, так и подпитку от экстракторов через балансировочные разветвители.
