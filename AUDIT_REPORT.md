# Отчет о техническом аудите проекта «FICSIT Town Manager» (Satisfactory 1.0)

Дата аудита: 2026-10-15
Версия проекта: 0.0.0 (Satisfactory 1.0 Release Spec)
Команда аудита: Software Architect, Senior Software Engineer, Security Engineer, QA Engineer, Performance Engineer, DevOps / SRE Engineer, Product Engineer.

---

## 1. Резюме состояния проекта

- **Тип проекта**: Client-Only Single Page Application (Static Web App).
- **Стек**: React 19.3.0, Vite 5.4.21, TailwindCSS 4.3.3, Zustand 5.0.15, @xyflow/react 12.12.0, Dagre 0.8.5, javascript-lp-solver 1.0.3, IndexedDB W3C.
- **Статус сборки**: Успешно (`npm run build` создает dist без ошибок).
- **Статус тестов**: 32 теста Vitest проходят успешно.
- **Ключевой вывод**: Проект функционален и обладает качественным UI, однако выявлены подтвержденные критические дефекты в логике персистентности, развертке графов, базе рецептов Satisfactory 1.0, потенциальные падения UI и неоптимальные блокировки основного потока.

## 2. Подтвержденные дефекты и проблемы

### P0 — Критические дефекты и целостность данных
1. **BUG-01 (Хранилище)**: Некорректный порядок слияния в `initStorage()` (`useFactoryStore.js:255`). Синхронный легковесный кэш из `localStorage` (не содержащий массивов `nodes` и `edges`) перезаписывает полные снимки из IndexedDB: `{ ...stages, ...currentFrozen }`. В результате теряется возможность мгновенной загрузки замороженного этапа (0 ms bypass).
2. **SEC-01 (Безопасность/Данные)**: Отсутствие валидации и санитайзинга импортируемых резервных копий в `importBackupJSON()` (`storageService.js:264`). Поврежденный или вредоносный JSON может повредить хранилище или привести к крашу приложения.

### P1 — Корректность расчетов и графа производства
3. **BUG-02 (Движок графов)**: В `realisticGraphEngine.js` узлы `isVIP` (VIP Junction контур рециркуляции воды) теряют входящие ребра от источников вторичной воды. В результате на схеме реалистичного цеха разрывается гидроконтур.
4. **BUG-03 (База рецептов)**: В пресете `complex_7` (`campaignPresets.json:284`) указан рецепт `electrode_aluminum_scrap` и выделен транзит 300 нефтяного кокса с этапа `power_4a`. Однако рецепт с таким ID отсутствует в `recipes.json`. Солвер не может использовать кокс и требует добывать уголь.
5. **BUG-04 (Солвер/Входы)**: При дублировании входных лимитов на один и тот же предмет в `solver.js:143` генерируются узлы с одинаковым ID (`import_${inp.itemId}`), нарушая инвариант уникальности узлов ReactFlow.

### P2 — Интерфейс и пользовательские функции
6. **BUG-05 (Краш компонента)**: `DeficitAlerts.jsx:8` пытается деструктурировать `deficits` из `useFactoryStore()`. Свойство `deficits` отсутствует в сторе; монтирование компонента вызовет фатальный `TypeError: Cannot convert undefined or null to object`.
7. **UX-01 (Фиктивные настройки)**: Поля «Доступные энергомодули» (`powerShards`), «Доступные Петлевики» (`somersloops`), «Применять строения повторно» (`reuseBuildings`) в `SettingsTab.jsx` не учитываются в расчетах `solver.js`.
8. **UX-02 (Ассеты/404)**: В `index.html` фавиконка ссылается на `/icons/Buildings/Constructor.png`, которого нет на диске, а абсолютный путь на GitHub Pages ломается из-за подпапки `/ficsit-town-manager/`.
9. **UX-03 (Экспорт в Firefox)**: В `ExportImageButton.jsx:97` ссылка для скачивания SVG вызывается через `.click()` без предварительного добавления в DOM (`document.body.appendChild`), что блокируется браузером Firefox.

### P3 — Производительность и сопровождаемость
10. **PERF-01 (Блокировка UI)**: Синхронный пересчет и Dagre layout на крупных этапах (`complex_3`, `phase_5`) занимают от 1.3 до 1.76 секунд в основном потоке JS.
11. **PERF-02 (Избыточные перерендеры)**: Компоненты (`GraphCanvas`, `MainView`, `RightPanel`) подписаны на весь стор `useFactoryStore()` без селекторов, вызывая каскадные ререндеры.
12. **DEAD-01 (Мертвый код)**: `RecipeSelectDropdown.jsx` не используется (дублирует `RecipeSelectorDropdown.jsx`). Имеются неиспользуемые ассеты (`src/assets/hero.png`, `vite.svg`, `typescript.svg`).

### P4 — Качество проекта и CI/CD
13. **OPS-01 (CI/CD)**: В `.github/workflows/deploy.yml` используется `npm install` вместо детерминированного `npm ci`, отсутствуют шаги тестирования (`npm test`) перед развертыванием.
14. **SEC-02 (Уязвимости)**: 6 уязвимостей в dev-зависимостях (`tinypool`, `vitest`, `vite`).
