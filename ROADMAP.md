# 🗺️ Планы развития и Архитектура (ROADMAP)

Этот документ содержит концепты и планы будущих масштабных обновлений для проекта **FICSIT Architect (Satisfactory Tools)**.

---

## 🌍 1. Глобальная карта логистики (Macro Map)

**Суть:** Режим визуализации, позволяющий охватить взглядом мировую логистику всей карты игры одним кликом, без погружения в микро-схемы станков.

### Архитектурный концепт:
- Вместо графа станков на холсте отображаются **Огромные квадратные блоки-Цеха** (например: «ЭТАП 1: Бетонный хаб», «ЭТАП 6: Тяжелое машиностроение»).
- Транзитный движок (`campaignTransitEngine.js`) генерирует связи (Edges) между этими макро-блоками.
- Между цехами тянутся толстые линии логистики (символизирующие Поезда, Дроны, Тракторы или Ленты) с подписями передаваемого сырья: *«Бетон: 344/мин»*, *«Пластик: 160/мин»*.
- **Польза:** Игрок мгновенно понимает, какой завод кормит другой завод, и где образуются узкие места в межзаводской транспортной сети.

## 🏭 2. Модуль «Реальный цех» (Micro Layout / Floor Plan)

**Суть:** Превращение математического калькулятора (где 10.4 плавильни — это абстрактная цифра) в генератор физических 2D-чертежей (САПР). Детальная поштучная развертка каждого станка, конвейера и сплиттера.

### Шаг 1: Распаковка макро-узлов (Unpacking)
Алгоритм берет абстрактный узел (например, `Ассемблер x5.2`) и разбивает его на физические машины:
- 5 станков с настройкой мощности **100%**.
- 1 станок с настройкой мощности **20%**.

### Шаг 2: Генерация Разделителей и Объединителей
- Алгоритм автоматически проектирует **Манифольды (Коллекторы)** — прямую ленту, от которой ресурсы отводятся в каждый станок.
- В граф динамически добавляются новые типы узлов: `SplitterNode` (Разделитель) и `MergerNode` (Объединитель).

### Шаг 3: Проверка лимитов лент (Belt mk.X Limits)
- Микро-движок проверяет максимальную пропускную способность конвейеров игрока.
- Если в цех заходит 1500 руды/мин, а максимальная лента вмещает 780, алгоритм автоматически разделит цех на **два параллельных манифольда**.

### Шаг 4: Кастомная физическая укладка (Custom Grid Layout)
- Алгоритм `Dagre` отключается для этого режима.
- Внедряется собственный **Grid Layout**: станки выстраиваются строго по сетке по оси Y. Слева строго по линейке выстраиваются Сплиттеры, справа — Мерджеры.
- Линии конвейеров (Edges) переключаются с плавных кривых (`bezier`) на строгие прямые углы (`smoothstep`), создавая вид инженерного чертежа (схемы печатной платы).

## ⚡ 3. Умный Планировщик Электропитания (Smart Power Planner)

**Суть:** Уход от простых таблиц (как в SCIM) к сквозному расчету производственных цепочек энергоносителей и интерактивным SCADA-дашбордам.

### Главные концепты:
1. **Сквозной расчет (End-to-End):** Энергетика — это тоже завод. Движок не просто говорит "Нужно 15 кубов Турботоплива", он автоматически передает эту цифру в солвер, который строит **цельный граф** от нефтяной помпы до топливного генератора.
2. **Wizard UI (Каскадный выбор):** Пошаговый конфигуратор. Игрок вводит целевую мощность (МВт) ➔ Выбирает тип генератора ➔ Выбирает тип топлива.
3. **SCADA-Дашборд:** Красивая футуристичная панель:
   - **Спидометр (Gauge Chart):** Отображает целевую генерацию.
   - **Блок оверклокинга:** Ползунок "Разгон осколками". Тянешь ползунок — количество генераторов в реальном времени уменьшается.
4. **Умная логистика воды (Supplemental Load):** Перевод литров в здания. Указание точного числа Водяных Помп и разбивка на идеальные контуры для труб Mk.2 (по 600 м³), чтобы избежать ошибок с пропускной способностью.

## 🔒 4. Фиксация постройки (Freeze Stage)

**Суть:** Заморозка математических расчетов для уже построенных заводов, превращающая калькулятор в полноценный трекер прогресса прохождения игры.

### Архитектурный концепт:
1. **Снапшоты графа (Zustand Snapshot):** При нажатии кнопки «Построено» (🔒) текущее состояние графа (`nodes`, `edges`) жестко кэшируется в локальной БД (внутри стора).
2. **Read-Only режим:** Панель настроек замороженного этапа блокируется, защищая завод от случайных изменений.
3. **Обход Солвера (LP Bypass):** Алгоритм линейного программирования не тратит ресурсы на пересчет замороженных этапов. Они загружаются за 0 мс, повышая производительность приложения.
4. **Изоляция рецептов:** Глобальное включение новых альтернативных рецептов не ломает старые, уже физически построенные заводы.
5. **Транзитная логистика:** Замороженные заводы продолжают стабильно поставлять свои кэшированные продукты (Outputs) в мировую транзитную сеть для питания новых цехов.

## 📚 5. Прочие запланированные модули
1. **Экономика купонов (AWESOME Sink):** Калькуляция стоимости профицитных деталей в купонах/мин.
2. **База Знаний (Wiki/Энциклопедия):** Внутриигровая справка по каждому предмету, где он используется и как производится.
3. **Blueprint 3D Viewer:** Чтение `.sbp` файлов и предпросмотр чертежей через Three.js.
